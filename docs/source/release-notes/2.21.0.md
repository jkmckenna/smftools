(v2.21.0)=

2.21.0 2026-08-26
Version 2.21.0 makes every pipeline stage publish immutable, checksummed generations the way raw
already did, adds selective POD5 re-basecalling as a first-class lineage that a project can hold
beside the original, gives an experiment a canonical identity that survives renaming, and reworks
the deaminase path from per-molecule segmentation through to variant acceptance. It also corrects
a duplicate-detection defect that has been inflating library complexity on fragmented libraries.

## Every stage publishes an immutable generation

Preprocess, spatial, hmm, and latent now publish the way raw has since 2.20.0: a checksummed,
self-describing generation directory selected by an atomic `current.json` pointer, with retention
recorded separately so pinning never edits a published manifest.

- `smftools experiment generations` lists what exists, with sizes, and pins a generation with a
  reason. `prune --keep-last` plans a deletion but does not perform one: destructive pruning stays
  blocked until byte-level reproducibility from retained inputs is represented authoritatively.
- Stage reuse is scoped to the settings that can actually affect that stage, so changing a spatial
  parameter no longer invalidates preprocess.
- Per-stage algorithm versions are live: the run gate honours `algorithm_version` the way the
  planner already did, so a fixed algorithm cannot silently reuse output built by the broken one.
- Upgrade impact reporting states which generations a version change invalidates before you run.
- Staging trees left behind by a run that died mid-publish are swept rather than accumulating.

## Selective re-basecalling produces a lineage, not a replacement

A subset of reads can be re-basecalled from POD5 with a different model, and the result is
published as an immutable descendant lineage that coexists with the original.

- POD5 sources carry a durable origin identity, so a relocated or historical POD5 set resolves
  without depending on its path.
- Planning is read-only. A selection is frozen before execution, so what runs is what was reviewed.
- Downstream stages run *inside* the lineage: a descendant raw stage, then preprocess, spatial, hmm
  and latent, all within one transaction.
- A project holds original and re-basecalled lineages side by side and answers with exactly one of
  them; `list_experiments` refuses to pool two lineages of the same experiment.
- A re-basecall request fans out across a project's experiments, and a lineage is validated before
  it can become the project's answer.

## Experiments have a canonical identity

- Experiment identity is validated across the directory name, config, manifest, and `project add
  --id`, so one run cannot acquire different labels depending on which fallback a command reached
  for.
- Renaming an experiment is transactional.
- The experiment manifest stamps the code identity that produced it.
- The identity resolver is versioned, so fixing it cannot silently reuse a sidecar written by the
  old one.

## The deaminase path is chemistry-aware

- Deamination is segmented per molecule by penalized change points, and the number of switches is
  inferred from a BIC-style cost rather than being fixed.
- Variant acceptance is taken from the covering deamination segment and the read's own strand,
  instead of applying one global rule.
- A read is only flagged a reference-switching chimera with adjacent informative-site support
  (`variant_chimera_min_adjacent_sites`, default 2), and `omit_chimeric_reads` honours every
  chimera method rather than one.
- Segmentation runs before variant evidence and excludes candidate sites, and is parallelized
  across read batches.

## Barcode contamination is measured, not assumed

An unbarcoded spike-in amplicon pooled with the libraries carries no barcode of its own, so any
barcode observed on one of its reads is a mis-barcoding event by construction. That gives a direct
contamination measurement per barcode.

- `mismatch` (both ends read, naming different barcodes) is reported as its own demux type instead
  of being folded into `unclassified`, which means "no usable barcode was seen".
- An `unclassified` directory is an assignment, not a barcode.
- Demux status is derived from the sequencing summary, and re-derived from sequence on
  already-demuxed input so single- versus double-ended status is recoverable from a FASTQ tree that
  does not carry it. The assigned barcode stays authoritative; disagreements land in
  `obs["barcode_agreement"]`.
- Enrichment is divided by the whole population rather than by demux type, and barcodes with thin
  denominators are reported separately rather than ranked at the top of the table.

## Duplicate detection no longer depends on read span

Duplicate detection scores only overlapping positions, but its candidate generation did not: the
sort key filled unmeasured positions with a sentinel, so two reads agreeing perfectly over their
overlap but differing in span sorted far apart and were never compared. Fragmented libraries were
therefore reporting duplicates as distinct molecules.

Candidate generation now also bands reads within anchor windows keyed only on columns every banded
read measures, with the window geometry derived from
`duplicate_detection_min_overlapping_positions` so any pair the comparison would accept can reach a
window. Distances are unchanged.

On a rapid-kit deaminase library of 14,358 reads (median read length 585, p10 144, p90 1,960),
duplicates rose from 53.0% to 61.5% and apparent unique molecules fell from 5,496 to 4,508 — an
**18% fall in estimated library complexity** — at a 15% increase in preprocess stage time. Of the
990 newly-duplicate reads, 89.4% overlap their cluster partner by 500 or more positions, so these
are not artifacts of the minimum-overlap floor.

## Latent clustering, clustermaps, and plots

- Each latent embedding is clustered in its own coordinates, with per-strategy Leiden resolutions.
- Latent-ordered clustermaps render three projected layers, with rows ordered by cluster and then
  within cluster.
- Stacked Leiden composition barplots, per-read mismatch clustermaps, and deamination segment
  clustermaps are added to their stages' plot catalogs.
- Automated position-correlation matrices are capped by read count, and short genome-mode
  references get a fallback plot region instead of silently producing nothing.

## Scaling

Several stages accumulated results in memory before writing them.

- Position matrices, deamination results, and task arguments are streamed to disk rather than
  materialized in full.
- Duplicate-detection groups are dispatched together instead of one at a time, and group workers no
  longer start nested pools — a real run went from 1-2 of 12 cores busy to a full pool.
- Admission polls for headroom before declaring a task unadmittable.
- Raw extraction, identity reconciliation, and extraction planning report progress.

## Behavior changes

No public API was removed. These change results or run behavior:

- **Duplicate detection finds more duplicates**, so library complexity estimates fall. The new
  config keys join the preprocess semantic fingerprint, which means **every existing preprocess
  generation is stale and will recompute on upgrade**. Set
  `duplicate_detection_span_agnostic_banding: False` to keep the previous behavior.
- `invert_adata` is refused rather than ignored. It did nothing in the partitioned pipeline, so a
  config asking for inverted data silently received uninverted data. Use `reindexing_invert`, which
  projects the display coordinate system without altering stored data.
- `bypass_deamination_segmentation` now defaults to `True`. PELT segmentation cost roughly two
  hours on a 1.3M-read run while changing zero chimera calls and about 0.03% of variant calls. Set
  it `False` to recover `deaminase_segment_chimera`, the segment plots, and segment-aware variant
  acceptance.
- `unclassified` reads are no longer treated as a barcode, and `mismatch` is no longer folded into
  `unclassified`. Consumers selecting on `demux_type` with a `["single","double","already"]`
  allowlist are unaffected.
- Config keys are scoped to the stages they affect, so a stage may now legitimately skip where it
  previously recomputed.

## Known limitations

- `generations prune` is a dry-run planner. It protects current, pinned, unreadable, recent, and
  newest generations, and does not delete.
- The duplicate-detection change is qualified on one fragmented library. Whether
  `duplicate_detection_hierarchical_max_representatives` can now be lowered — with anchored banding
  on, capping it at 50 rather than 5000 changed the result by 0.01 points — rests on that same
  single run and is deliberately not acted on.
- Re-basecalling end-to-end coverage skips when Dorado, its model directory, or modkit is absent.
